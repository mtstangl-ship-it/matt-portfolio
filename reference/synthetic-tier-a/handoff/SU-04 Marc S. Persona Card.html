SU-04 · MOBILE LOGIC

The label gutter collapses. Each field's mono label sits directly above its value rather than beside it — the spec-sheet rhythm holds vertically, and no value gets squeezed into a narrow column.

The name and first question stay the two loudest elements; both scale down but never demote below the surrounding fields. The persona's lens still leads.

The finding block is protected — it keeps its border, its FAIL flag, and the Autodesk reference at full weight. On a phone it's the last thing a reader sees, and it should still read as a logged event, not a footnote.

The archetype index hides at ≤560px (it's a set-navigation affordance, not card content), so the single card stands cleanly on its own.

§ 1 · The finding is the pointSelf-implicating credibility

What makes this card land is that the finding is a FAIL on a real case in the same portfolio — Autodesk. A persona card that praises itself proves nothing; one that catches a documented miss and logs a specific fix proves the method works. The verdict block is sized and bordered to read as a logged event, and the Autodesk reference is bold because the specificity is the credibility. This is the artifact's whole job: show, don't tell.

§ 2 · Why the spec-sheet formInstrument, not avatar

The five fields are a deliberate rhythm: anchor → question → pass → failure → finding. Setting them as a labeled spec sheet (mono gutter, dashed rules) signals "this is a research instrument," which is the frame the brief insists on. The first question gets display weight because it's the operative lens — everything the persona does flows from it. No photo, no demographic fluff; the worldview is the persona.

§ 3 · Risks for the port

  • Two-color discipline. Teal (accent) + orange (warning stamp) is the intended split. If Matt wants strictly one color, the FAIL flag can become a hollow/▲ outline with no orange — but the semantic loss is real; flag before removing.
  • Set index as chrome. The 5-archetype strip is card-system content, not page chrome — but verify it doesn't get mistaken for the site's case picker when ported into the live section.
  • Quote scale. The 22px first question is tuned for a ~640px card. If the live card is wider, cap the quote's measure (~46ch) so it doesn't run too long per line.
